This page lists every configuration key for the {BRAND_NAME} components. All components read the same configuration contract, so the same keys apply wherever a component runs. Docker Compose is the supported deploy target today.

Each Compose unit ships a commented `.env.example` (`deploy/self-hosted/hub/`, `deploy/self-hosted/bridge/`). Start from that file. It is not exhaustive; some integration keys on this page must be added by hand. See [Docker Compose](/self-host/docker-compose) for the deploy walkthrough.

## Images

| Key                   | Value                                  |
| --------------------- | -------------------------------------- |
| `BROKKR_APP_IMAGE`    | `hydrahost/brokkr-hub` (Docker Hub)    |
| `BROKKR_BRIDGE_IMAGE` | `hydrahost/brokkr-bridge` (Docker Hub) |

Both images are public and multi-arch (amd64 and arm64). New versions are published on each tagged release. To run a source-built fork, point these keys at your own registry.

## Identity keys

Three secrets define your installation's cryptographic identity. Generate each secret once and back it up. Rotation is a breaking event:

| Key                      | Runs on | Purpose                                                                            | Rotation invalidates    |
| ------------------------ | ------- | ---------------------------------------------------------------------------------- | ----------------------- |
| `BROKKR_HUB_PRIVATE_KEY` | hub     | X25519 private key (base64, 32 bytes) for zone enrollment and device-secret crypto | Every zone enrollment   |
| `DEVICE_TOKEN_PEPPER`    | hub     | Pepper for hashing device tokens at rest                                           | Every device token      |
| `BRIDGE_AT_REST_KEY`     | Bridge  | AES-256 at-rest encryption key for device secrets the Bridge caches                | The Bridge secret cache |

```bash
openssl rand -base64 32   # BROKKR_HUB_PRIVATE_KEY, BRIDGE_AT_REST_KEY
openssl rand -hex 32      # DEVICE_TOKEN_PEPPER
```

Each key fails loud when missing or malformed:

- `BROKKR_HUB_PRIVATE_KEY` unset: hub crypto stays dormant and every `POST /zones/<id>/enroll` returns 503, so no Bridge can enroll. Present but malformed: the hub throws at boot. Confirm the key loaded by checking the boot log for `Hub crypto loaded; hub_pub=<hex>`.
- `DEVICE_TOKEN_PEPPER` unset or blank: the hub fails closed. There is no fallback.
- `BRIDGE_AT_REST_KEY`: the Bridge refuses to start on the shipped placeholder. Generate the key once per zone and set the identical value on every Bridge in that zone, because they share the secret cache.

See [Secrets and device tokens](/security/secrets-and-device-tokens) for how these keys are used.

## Datastores

Postgres and Redis are the only hard dependencies:

| Key            | Purpose                                          |
| -------------- | ------------------------------------------------ |
| `DATABASE_URL` | Hub Postgres, the source of truth                |
| `REDIS_URL`    | Cache and the hub-to-Bridge message bus (BullMQ) |

The self-hosted hub Compose unit assembles `DATABASE_URL` from `PG_USER`, `PG_DB`, and `PG_PASSWORD`, and points `REDIS_URL` at the bundled Redis. On the Bridge, `REDIS_URL` points at the hub's Redis and includes the zone's Redis ACL credential.

<Warning>Keep Redis on a private network or VPN. Never expose `:5432` or `:6379` at the edge.</Warning>

## Auth and first admin

| Key                                            | Purpose                                                                                                                     |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET`                           | Session signing secret; rotating it invalidates all sessions                                                                |
| `BASE_URL`                                     | Public URL browsers hit, used for auth callbacks and CORS. Must match your TLS certificate                                  |

<Warning>
  The admin password is written only on first creation. Changing it in `.env` later does nothing. Change it away from
  well-known defaults before first boot on any reachable deployment.
</Warning>

## Zone identity (Bridge)

| Key                         | Purpose                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------ |
| `BROKKR_ZONE_ID`            | The zone's UUID from the hub UI. Also the Bridge's Redis namespace                               |
| `BROKKR_REGISTRATION_TOKEN` | Registration token minted on the zone's overview page. Shown once, single-use, expires after 24h |
| `BRIDGE_HOSTNAME`           | Unique name per Bridge, used for leader election and agent dial-back                             |

## OS asset sync

The Bridge image bakes in the iPXE binaries, the initrd overlays, and the bridge-agent bundle. It does not bake in the discovery OS image set (`vmlinuz`, `initrd.img`, `brokkr-discovery.iso`) that discovery PXE boot serves. Only sync populates that set. With `BRIDGE_SYNC_ENABLED=false`, the Bridge logs an error at boot while the set is missing and discovery boots fail. Startup continues unless `BRIDGE_DISCOVERY_IMAGES_STRICT=true`. Set `BRIDGE_SYNC_ENABLED=true` to pull the set from an asset host. When sync is on, you must also set `DISCOVERY_BASE_URL`, because its built-in default is a non-resolving placeholder. `BROKKR_LIVE_VERSION` defaults to a real version (`1.0.4`); set it only to pin a different one:

```bash
DISCOVERY_BASE_URL=https://assets.example.com/brokkr-live
BROKKR_LIVE_VERSION=1.0.4
```

With sync enabled, a defined-but-empty `DISCOVERY_BASE_URL` builds a broken sync URL. Leave the variable unset so the sync at least fails on the placeholder. When sync is off, `DISCOVERY_BASE_URL` is inert. `BROKKR_LIVE_VERSION` is still read on every registration heartbeat and reported as `brokkr_live_version` in the Bridge's instance registry. In that case it is reporting-only metadata, and nothing is downloaded.

`OS_LAYER_URL` is independent of the sync toggle. The Bridge never downloads OS-customization [layers](/os-builds/layers). Provisioned machines fetch layer blobs from `<OS_LAYER_URL>/sha256:<hash>` at deploy time. Its default is another non-resolving placeholder, so set it whenever you deploy layer-based OS builds:

```bash
OS_LAYER_URL=https://assets.example.com/os-layers/blobs
```

<Note>
  The Bridge validates `OS_LAYER_URL` on every boot regardless of the sync toggle. A defined-but-empty value fails loud
  and blocks startup.
</Note>

## Integrations

Integrations are [plugins](/extend/plugins-overview) that enable themselves when their full variable set is non-empty. Leave a key empty or unset to disable its integration. A missing key never fails the boot; the hub silently disables the plugin.

| Integration        | Variables                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Mailgun (email)    | `MAILGUN_API_KEY`, `MAILGUN_DOMAIN`, `MAILGUN_FROM_ADDRESS`                                                               |
| Radar (geocoding)  | `RADAR_SECRET_KEY`                                                                                                        |
| HubSpot (leads)    | `HUBSPOT_ACCESS_TOKEN`, `HUBSPOT_PORTAL_ID`, `HUBSPOT_CONTACT_OWNER_ID`, plus the demand-request form and object-type IDs |
| Salesforce (leads) | `SALESFORCE_MY_DOMAIN_URL`, `SALESFORCE_CLIENT_ID`, `SALESFORCE_CLIENT_SECRET`                                            |

When both HubSpot and Salesforce leads are configured, HubSpot stays active and Salesforce is disabled. Clear the `HUBSPOT_*` variables to switch.

The hub `.env.example` also carries keys no self-hosted deployment can use. The Pylon helpdesk plugin (`PYLON_API_TOKEN`, `PYLON_ACCOUNT_ID`, `BROKKR_ADMIN_ORG_ID`) and the ClickHouse analytics plugin (`CLICKHOUSE_*`) are proprietary. They ship only in internal managed builds and are absent from the open-source tree. The self-hosted hub logs each proprietary plugin as `not installed (BOSS tree)` and skips it at boot, ignoring their keys, whether you run the published image or build from source. The `VAULT_*` and `NETBOX_*` keys are inert; no hub code reads them. Keep the shipped placeholders as-is.

## White-label branding

Nine `VITE_*` variables brand the web UI. The web build reads them at build time (`import.meta.env`), so the published images ship the defaults. Exporting them at `docker build` time is not enough: the hub Dockerfile declares no `VITE_*` build args, and the build context excludes `.env` files. To rebrand, add `ARG` and `ENV` lines for these variables to `apps/api/Dockerfile` and build the hub image from source. Alternatively, set them in the shell and run the web build (`pnpm build`) outside Docker.

| Variable             | Default                       |
| -------------------- | ----------------------------- |
| `VITE_BRAND_NAME`    | `BoSS`                        |
| `VITE_COMPANY_NAME`  | falls back to the brand name  |
| `VITE_SUPPORT_EMAIL` | `support@example.com`         |
| `VITE_LEGAL_EMAIL`   | `legal@example.com`           |
| `VITE_COMPANY_URL`   | `https://example.com`         |
| `VITE_TERMS_URL`     | `<company URL>/terms`         |
| `VITE_PRIVACY_URL`   | `<company URL>/privacy`       |
| `VITE_SECURITY_URL`  | falls back to the company URL |
| `VITE_HELPDESK_URL`  | empty                         |

`VITE_COMPANY_URL` must be an `http://` or `https://` URL; anything else falls back to the default, and trailing slashes are stripped.

## GPU category catalog

The marketplace category cards (name, chipset, description, badges, and CTA) live in one static module: `apps/web/src/lib/category-data.ts` (`inventoryCategories`). The catalog is compiled into the SPA and is not environment-driven. Edit the array and rebuild the web app to change it. The displayed starting price is the exception. Every inventory route merges live category pricing and availability from the hub API over the static array (`mergeCategoryPrices`), so the hard-coded `startPrice` only shows when no live price matches the chipset.

### Brokkr Live Agent

The agent takes its identity and endpoints from the agent.yaml baked into its initrd by the Bridge; no variable is required for it to start.

| Variable                            | Default              | Required | What it controls                                                                            |
| ----------------------------------- | -------------------- | -------- | ------------------------------------------------------------------------------------------- |
| `AGENT_LOG_LEVEL`                   | agent.yaml value     | no       | Minimum log level for the agent logger; a valid value overrides agent.yaml                  |
| `BRIDGE_PLUGIN_HELLO_WORLD_ENABLED` | `false`              | no       | Set `true` to enable the hello world example plugin device operations                       |
| `BROKKR_HOSTS_FILE`                 | `/etc/hosts`         | no       | Hosts file the agent rewrites with Bridge name to IP entries on topology updates            |
| `DEVICE_ID`                         | lockscreen.env value | no       | Device identifier printed on the lockscreen banner; display only                            |
| `JOB_ID`                            | lockscreen.env value | no       | Provisioning job identifier printed on the lockscreen banner                                |
| `LOCAL_SIMULATION_ENABLED`          | `false`              | no       | When `true`, the public IP collector reports a placeholder instead of querying the internet |
| `LOCKSCREEN_INTERVAL`               | `10`                 | no       | Lockscreen refresh interval in seconds                                                      |
