# Theming

The design system themes along **three orthogonal axes**, written as attributes on `<html>` by
`ThemeProvider` (`@repo/ui/theme-provider`):

- `data-style` — **retro** (square, techy, JetBrains Mono) or **modern** (rounded, calm, Inter)
- `data-color` — **violet**, **blue**, **green**, **pink**, or **gold**
- `data-mode` — **dark** or **light** (always the resolved mode; "system" is a stored
  preference, never a DOM value)

Every combination works: 2 styles × 5 colors × 2 modes = 20 themes.

See the live [Themes gallery](?path=/story/foundations-themes--gallery), the
[style comparison](?path=/story/foundations-themes--comparison), and the resolved
[token values](?path=/story/foundations-colors-tokens--default) for the active theme.

## How the CSS is organized

`@repo/ui/styles/brokkr.css` is an aggregator over `packages/ui/src/styles/`:

- `theme-base.css` — the Tailwind `@theme` block (declares every token and generates the
  utilities) plus the shared re-binding rule for `var()`-composed aliases.
- `modes.css` — `data-mode` only sets `color-scheme`. Every mode-varying token is written once
  with `light-dark(lightValue, darkValue)` and resolves against the `color-scheme` of the
  element that uses it.
- `colors.css` — one `[data-color='…']` seed block per color (`--seed-accent-strong`, mid
  `--seed-accent`, `--seed-accent-deep`) plus the shared mapping onto the accent family.
- `style-retro.css` — square radii, JetBrains Mono, and neutrals tinted by the color seeds via
  `color-mix()`, so every color carries through backgrounds and text.
- `style-modern.css` — rounded radii, Inter, fixed neutral zinc/white neutrals (color reaches
  only accents and their tints), and the modern structural rules (corner ticks hidden, closed
  rounded form fields, calm tables).
- `base.css` — resets, keyframes, and pattern helpers.

### Adding a color

One seed block in `colors.css` plus one `THEME_COLORS` entry in `theme-provider.tsx`. The
`theme-axes.spec.ts` drift test asserts they stay in sync.

## ThemeProvider

`ThemeProvider` owns the axis attributes on `<html>` and persists three localStorage keys:
`brokkr-style`, `brokkr-color`, and `brokkr-mode` (`dark`, `light`, or `system`). Pre-axis keys
(`brokkr-theme`, `brokkr-preferred-dark/light`) are migrated on first load and removed — the
old `solarized-light` theme becomes retro / violet / light.

The pre-axis `data-theme` attribute is no longer a supported CSS API: no stylesheet responds to
it, and both `ThemeProvider` and `theme-init.js` strip it from `<html>`. Code that still sets
`data-theme` must switch to the three axis attributes (or to `ThemeProvider` / `ThemeScope`).
`terminal-theme.css`, which is also exported standalone, keeps a literal fallback for
`--color-accent-foreground` so it stays legible without the axis stylesheets.

The context exposes `{ style, color, modePreference, resolvedMode }` and the setters
`setStyle` / `setColor` / `setMode`. `system` mode follows the OS `prefers-color-scheme` live
via a media-query listener.

`ThemeSelector` (`@repo/ui/theme-selector`) is the ready-made dropdown over this context, and
`ThemeSettingsPanel` (`@repo/ui/theme-settings-panel`) is the full settings page body; in this
Storybook the toolbar controls drive the same provider.

Apps also ship `public/theme-init.js` (canonical copy in `packages/ui/theme-init.js`, byte
equality asserted by `theme-init.spec.ts`) to apply the attributes before first paint; per-app
defaults ride on the script tag as `data-default-style/color/mode`.

## Forcing a theme on a subtree

`ThemeScope` (`@repo/ui/theme-scope`) pins a subtree to a fixed theme — no provider needed.
Apps use this for hosted pages that must ignore the visitor's saved theme:

```tsx
<ThemeScope style="modern" color="violet" mode="light" className="bg-bg-primary text-text-primary">
  {/* everything in here renders modern / violet / light */}
</ThemeScope>
```

Two rules:

- **Always set the complete triple.** Axis tokens are substituted at the element that declares
  them, so a wrapper carrying only one attribute inherits values already baked against the
  root's other axes. `ThemeScope` makes the triple mandatory.
- **Nest modern scopes inside retro ones, never the other way around.** The modern structural
  rules are ancestor-scoped descendant selectors, so a retro scope nested inside a modern one
  still gets the flat/rounded treatment.

The [Themes gallery](?path=/story/foundations-themes--gallery) story uses exactly this
technique to render every combination side by side.
